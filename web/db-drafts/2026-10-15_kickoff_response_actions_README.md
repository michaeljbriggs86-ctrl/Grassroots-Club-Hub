# Kick-off response actions — applied database change

Applied to the live database on 16 October 2026 as **20261016170624_kickoff_response_actions**, following Mike's continuation of the explicitly named release proposal. The migration mirror preserves the exact tested SQL bytes (SHA256 `b0f4eba6351d06d0f0429351a2f4e918382ebc1463fe5f2dd56b291fcdf23100`), including its original candidate header. It creates no invitations, releases, delivery jobs or real responses. Website release and served verification are recorded separately in the dated immutable handoff.

Reviewed Figma scope: [board 370:6986](https://www.figma.com/design/NY8QhcuOWiEcD0pKDTsbP8?node-id=370-6986), including the explicit-action/read refinement on 15 October and Confirm-only refinement on 16 October 2026.

`2026-10-15_kickoff_response_actions.sql` adds a separate coach acknowledgement timestamp and private own-child evidence pointing to an existing availability row and its timestamp. Attendance remains in `public.match_availability`; its status is not duplicated. The predecessor definitions are fingerprinted against the read-only live catalog before replacement, and existing function grants are preserved.

- `acknowledge_kickoff_as_coach(p_update_id)` records an idempotent acknowledgement for an addressed, currently eligible coach in Staff capacity. It returns `update_id`, `revision`, `coach_acknowledged_at` and `read_at`.
- `respond_kickoff_parent_availability(p_update_id, p_parent_link_id, p_status)` accepts `available` or `unavailable` for an own linked child in Parent capacity. It atomically writes canonical availability, current-version evidence and the parent's seen/read timestamps, then returns the refreshed personal card.
- `list_kickoff_updates_for_me()` adds capacity-specific actions and own-child response states. It returns no other family's identities. The old checkbox RPC is retained only as a staff compatibility wrapper; historic ambiguous `seen_at` values are not converted to coach acknowledgements.
- `list_kickoff_updates_for_admin(p_team_id default null)` returns current upcoming releases, named addressed coaches who remain eligible and aggregate child availability. It requires an active verified Club Admin in Staff capacity and does not require the Admin to have received the release. Coaches assigned after a release, or recipients who were not addressed as coaches, are excluded from that release's coach totals. This does not backfill deliveries or show an acknowledgement request that the coach cannot answer.

Both actions lock the same team-state row as fixture saves and reject superseded or withdrawn details. Only an explicit successful action marks that actor's notice read; opening, ordinary read actions and delivery do not acknowledge or set attendance. Failure rolls the entire action back, and retries preserve the first acknowledgement/read timestamp.

Cup keys and legacy reads match `fixtureResponseKey`, `miniCupGroup` and the existing availability display. The newest effective availability row determines whether evidence remains current. A later Home, Coach or legacy write invalidates old response evidence without deleting the attendance answer. An unchanged parent answer avoids rewriting the canonical row, so confirming the second cup game does not invalidate the first unnecessarily. Staff accounts replying in Parent capacity retain parent provenance.

Verification: `node web/db-drafts/test/run-kickoff-response-actions.cjs` runs the disposable PostgreSQL suite, including 26 app/SQL key-parity cases, permission boundaries, multiple children, dual capacities, legacy freshness, revision rejection, explicit-action/read rollback and grant preservation. No production database or delivery endpoint is used.
