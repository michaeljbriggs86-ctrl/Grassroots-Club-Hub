# Kick-off update delivery

Priority 3 continuation, 15 October 2026. Candidate until actual deployment/catalog readback; independent device/inbox acceptance is separate.

Reviewed UI: https://www.figma.com/design/NY8QhcuOWiEcD0pKDTsbP8?node-id=285-6351 . A committed change to an upcoming valid UK-local kick-off, public venue or confirmation status creates private versioned adult receipts. Opening/read/delivery is separate from the explicit checkbox acknowledgement. No player audience, other club rollout or historical send backfill.

Apply only the scoped kickoff_updates and kickoff_dispatch_schedule migrations in prerequisite order; never db-push unrelated candidates. Keep the private tables inaccessible to browser roles. Active, verified, unbanned Shooters Hill staff and linked parents are rechecked at send time. Push endpoints are restricted to literal supported vendor hosts. Outbox claims expire and retry at most five times; withdrawn or superseded details are not sent.

Supabase supplies the existing service-role authority to the Edge runtime. Generate kickoff_dispatch_token inside Vault, never in source/chat/cron text. The token-validated service-only kickoff_dispatch_configuration RPC returns only this feature's credentials. On the first authenticated, empty-queue run while transport flags are off, the Edge runtime generates a P-256 VAPID pair and installs it using install_kickoff_signing into Vault as kickoff_vapid_credentials. The private signing key stays inside Edge/Vault. Concurrent/replayed installation cannot rotate a stored pair. No extra SMTP password or Supabase dashboard credential entry is needed.

Email uses the existing native Cloudflare club email binding, Hello@pitchkind.com sender and secretary reply address. The Edge sends only a job ID and expiring claim token to /__kickoff_mail. Anonymous capability redemption binds recipient and public fixture content on the server, rechecks current eligibility and consumes the lease once. It cannot accept caller-supplied recipient/content/link. The Worker returns sent only with a provider message ID; rate limits/internal failures retry and permanent rejection fails. Service acceptance is not inbox delivery. Crash/retry between service acceptance and the database receipt can rarely duplicate an email; no exactly-once external delivery claim is made.

Deploy kickoff-dispatch with verify_jwt=false because its custom Bearer token is checked via the service-only Vault guard. Browser JWTs and malformed/bad tokens cannot reach the outbox. The once-per-minute private cron invocation reads its token from Vault; no literal credential appears in job SQL. Public VAPID configuration and channel flags are service-only administration. Each channel has its own activation timestamp, so activation does not send earlier queued updates.

No live recipient, account, child or acknowledgement is created as a test. Verify actual function source, grants/RLS, the native binding and fixed-origin HTTP guards, a zero-outbox authenticated dispatcher run and scheduled invocation before any live claim. Use only user-authorised real future fixture changes for operational sends. Keep actual inbox/device receipt and Claude acceptance explicitly open until checked. Push opt-in remains a deliberate action on each supported browser/PWA; native WebViews without Push API show unavailable. Logout unsubscribes the current device; private data is never service-worker cached.
